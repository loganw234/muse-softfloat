## Design entry gates (write before any kernel code)

1. **Specials second-read.** Full 9.2.1 table for sinPi/cosPi
   in your own words: NaNs via `msf_nan_delivery` (sNaN signals;
   never infinity); +-inf -> invalid + default qNaN; exact
   zeros at integers/half-integers with signs - explicitly
   settle the two cells the spike flagged believed-not-second-
   read (cosPi half-integer sign, sinPi negative-integer sign)
   against the S1/SF-0 text and record *how*; |result|<=1 so
   no overflow ever; underflow by exact tiny-test on the wide
   value only; inexact exactly when the delivered value differs
   from the wide value.
2. **Error budget re-derived.** Your own derivation (script-
   computed, in scratch) of the per-stage total error bound Ek
   for your actual evaluation order: table quantum, u^2
   rounding, Horner accumulation, pi-table truncation, Taylor
   tails, delta-branch terms. The interval half-width in code
   must be >= the derived Ek at every width; "the spike said
   2^-24 fudge" is not a derivation.
3. **Stage-final behaviour.** State what the shipped code does
   if the final stage's interval still straddles a boundary
   (the design must make this unreachable under the leg-(c)
   argument, gates must instrument escalations test-only and
   show **zero** final-undecided hits across every gate set;
   any hit is an escalation/stop, never a shrug).
4. **Table generation.** Constants generated by your own
   `tools/gen_trig_tables.py` from first principles (pi and
   factorial values at >=640-bit MPFR/mpmath precision, exact
   rational rounding to limbs), byte-identical regeneration,
   dropped-low-limb truncation must be gate-visible.

`src/msf_trig_tables.h`; exact integer period/quadrant
reduction (no wide multiplication on the reduction path);
