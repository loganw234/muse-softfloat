Letter matching is ASCII case-insensitive. s==NULL is treated as no valid prefix (RULING 1 covers this too; recommend defensive +0/consumed 0/no flags rather than UB). The invalid flag is NEVER signaled by a malformed or finite parse; the only invalid sources in this TU are the NaN cases under RULING 2. ### Exact algorithms

Internal big integer: fixed array of 96 uint32 limbs (3072 bits) in this TU only, little-endian, with ops: set from u64, multiply by small (u32), multiply by 5^k and 10^k via repeated small multiplies grouped as 5^13 and 10^9 chunks, shift left/right by bits, compare, subtract, bit-length, divide-modulo by small (10^9) for digit extraction, and one general division (binary long division: align divisor under dividend, shift-subtract per quotient bit; at most about 220 quotient bits are ever needed, so cost is bounded and small). Width proof: the largest exact integers are (a) from_decimal with decimal exponent E, 10^|E| only built when the early-out thresholds have not fired, which bounds |E| <= 400, so 10^400 < 2^1330 and D*10^400 with D < 10^20 < 2^67 stays below 2^1400; (b) to_decimal exact expansion sig*5^k with sig < 2^53 and k <= 1074 (smallest f64 subnormal exponent), below 2^(53+2494) = 2^2547; 3072 bits covers both with margin, and every constructor asserts no limb overflow by construction checks in the generator's mirror tests. A static ceiling check returns through the overflow/underflow synthesis paths rather than ever truncating silently if a bound were mis-argued; the thresholds below make those paths unreachable for built bigints, which the directed vectors demonstrate at the boundary exponents.

from_decimal (after grammar, specials, zero-mantissa, beyond-H step): value = D * 10^E with 0 < D < 10^20 (u64 plus one carry bit handled by keeping D as a 2-limb start) and E a clamped int32. Decimal magnitude estimate m = (decimal digit count of D) + E, so value lies in [10^(m-1), 10^m). Early-outs, chosen only where the outcome is certain for the destination: if m-1 > 310 (f64; per-format constants 50/39/310 chosen so 10^(m-1) exceeds the overflow threshold (2-2^-p)*2^emax for every mode) deliver via msf_pack_generic(sign, exp2 = emax+2, sig = 1, sticky = 1) which yields overflow+inexact with the mode-correct infinity-or-largest-finite delivery; if m < -340 (f64; per-format -60/-50/-340 so 10^m is below half the smallest subnormal ulp 2^(emin-p-1) by a wide margin) deliver via msf_pack_generic(sign, exp2 = emin-p-4, sig = 1, sticky = 1) which yields underflow+inexact with the mode-correct zero-or-smallest-subnormal delivery; the generator reference cross-checks both synthesised deliveries against direct exact packing at and inside both thresholds so the synthesis is gated, not assumed. In the remaining band |E| <= 400: if E >= 0, N = D * 10^E exactly (bigint); reduce N to the pack input by taking its top 128 bits as sig with exp2 = bitlength-128 and sticky = any lower bit set (or sig = N, exp2 = 0 when shorter). If E < 0, DEN = 10^(-E); choose s = bitlength(DEN) + 200 - bitlength(D) (at least 0), compute Q, R = divmod(D * 2^s, DEN) by binary long division so value = (Q + R/DEN) * 2^-s with Q in [2^199, 2^201); reduce Q to its top 128 bits as above with sticky = (any reduced bit) OR (R != 0). Exactness of the reduction for msf_pack_generic: the pack contract is value = (sig + f) * 2^exp2 with f in [0,1) known only as zero-or-nonzero; the reduction gives exactly that, and because sig keeps 128 bits while the pack window needs p+2 <= 55 bits from the top plus a faithful sticky below the round bit (guaranteed since every bit below the round position is either inside sig or folded into sticky), the single pack rounding is the correctly rounded result of the exact decimal input, ties included (an exact tie has R/DEN and reduced bits producing guard=1, round=0, sticky=0 precisely). One pack call delivers bits and all flags.

from_hex: value = H * 2^(P - 4*fracdigits) where H is the significand as an integer. Build the pack input directly from the digit stream: accumulate hex digits into a 128-bit sig until full, thereafter count remaining digits into exp2 and OR their nonzero-ness into sticky; leading zero digits are skipped without touching exp2 except through the fracdigits count (handled by tracking digits-after-point and a started flag). P is clamped to +-100000 during its decimal parse (all digits still consumed). With sig possibly carrying trailing zeros from the accumulate-then-stop rule, value = (sig + f) * 2^exp2 exactly as the pack requires, f nonzero iff sticky; no early-outs needed because exp2 stays an int32 and the pack handles the full range (sig==0 with sticky set cannot occur: sticky is only set after a nonzero digit entered sig, and the all-zero significand short-circuits to signed zero first). Exact for any digit count by construction.

to_decimal: decode via msf_decode. Zero: digits are all '0', decimal exponent 0, sign preserved, no flags. Infinity and NaNs: fixed spellings above, spec ignored, no flags (except the RULING 2 signaling-output case). Finite nonzero: exact value sig * 2^exp. If exp >= 0, N = sig << exp as a bigint and the decimal digit string of N (by repeated divmod 10^9) with decimal exponent dexp = ndigits-1 is the exact expansion. If exp < 0, N = sig * 5^(-exp) and value = N * 10^exp, so the digit string of N with dexp = ndigits-1+exp is the exact expansion (finite, at most 767 digits for f64). Round the exact digit string once to K significant digits where K is the effective precision (spec section below), K <= 20: compare the dropped tail against exactly-half (first dropped digit 5 with all later dropped digits zero-or-absent) to decide ties exactly; ties-to-even keeps an even last kept digit, directed modes follow sign as in the beyond-H step; a carry renormalizes ('99..' up to '10..0', dexp+1). Inexact is signaled iff any dropped digit is nonzero. No overflow or underflow is ever signaled in this direction (the output exponent is unbounded in both styles and a nonzero input never rounds to a zero digit string at K >= 1). If the requested digit count exceeds 20 the emitted digits are the 20-digit correctly rounded result padded with trailing zeros (5.12.2), and inexact still reflects only the 20-digit rounding.

to_hex: decode; specials and signed zero as spellings 'inf', '-inf', 'nan', '-nan', 'snan', '-snan' per RULING 2 (NOT hex forms; 5.12.1 spellings govern NaNs and infinities in both output operations, RULING 2 bundles confirming this). Finite: the exact form is C-style 0x: normals are 0x1.<frac hex>p<e> with e the unbiased exponent; subnormals are 0x0.<frac hex>p<emin>; zero is 0x0p+0 (sign '-0x0p+0' for negative zero, RULING 5 covers zero/special surface spellings). Exact-enough (precision < 0): emit the fraction hex digits of the trailing field (13/6/3 nibbles for f64/f32/f16 with the f32/f16 trailing fields not nibble-aligned, so digits are taken from the value sig*2^exp shifted to a nibble boundary rather than from the raw field) with trailing zero digits trimmed and the '.' omitted when no fraction digits remain; never inexact. Explicit precision (RULING 5: recommend C %a semantics, precision = hex digits AFTER the point, precision 0 means no point and no fraction digits): round the exact binary value to that many fraction hex digits at the leading-digit scale (normals: 1.xxxx scale; subnormals: 0.xxxx at emin scale; zero: all-zero digits) using the binary rounding attribute on the exact dropped bits (guard is the top dropped bit, exact tie iff the dropped part is exactly half an ulp of the last kept hex digit), signalling inexact iff any dropped bit is nonzero; a carry may raise the leading digit (1.ff.. to 2.00.. keeping the same exponent, as C printf does, RULING 5) or a subnormal 0.ff.. to 1.00.. at emin. Precision larger than the exact digit count pads trailing zeros; length is computed arithmetically so a huge precision returns a huge would-be length without materializing it.

### Spec struct semantics proposed to freeze (header line 90 leaves these to this gate; RULING 5 is the bundle)

msf_decimal_spec_t: precision = significant digits requested; precision <= 0 selects Pmin (header). Emitted significant digit count N = max(precision_effective, min_digits if min_digits > 0 else 0); digits are COMPUTED (correctly rounded) at min(N, 20) and zero-padded from there to N, i.e. min_digits is a floor on the emitted count and raises the computed precision when it exceeds precision (the alternative, zero-padding from precision to min_digits without computing more true digits, makes min_digits emit knowingly false trailing digits while looking precise; recommend the floor reading, one test row distinguishes them: precision 2 min_digits 5 on 1.23456e0 gives 1.2346e+00 under my reading, 1.2000e+00 under the other). min_digits <= 0 means no floor. Style SCIENTIFIC (0): '[-]d[.ddd]e+XX' with exactly one digit before the point, the point present iff N > 1, exponent always signed with at least two digits, no leading zeros beyond that ('e+05', 'e-05', 'e+308', 'e+00' for zero). Style FIXED (1): the same N-digit significand and decimal exponent written positionally with no exponent letter: point position dexp+1 digits from the left; leading '0.' plus zeros when dexp < 0; trailing place-holder zeros when dexp+1 > N (no point then); examples precision 5: 123456.7 in FIXED is '123460', 0.0000123456 is '0.000012346', zero is '0.0000' (N digits total, point after the first zero when N > 1, plain '0' when N == 1). Any style value other than 1 is treated as SCIENTIFIC. spec == NULL uses the default {Pmin, SCIENTIFIC, no floor}. Inexact is signaled on the conversion regardless of whether the buffer fits (the header's write-nothing rule governs bytes, not flags; RULING 5 bundles this).

msf_hex_spec_t: precision < 0 exact-enough (header); precision >= 0 is fraction hex digits after the point per RULING 5 above; spec == NULL is exact-enough. Output letters are lowercase ('0x', 'a'-'f', 'p'), exponent always signed decimal with no leading zeros ('p+1', 'p-1022', 'p+0').

Buffer rule applied in both output ops: compute the full result length L (excluding NUL) arithmetically; if buf == NULL or buf_size < L+1 write nothing at all (not even a NUL) and return L; else write the characters and a terminating NUL and return L. L is computed in 64-bit and clamped to SIZE_MAX only in the pathological precision==INT_MAX fixed-style corner (return value saturates; no buffer can fit, nothing written; a named test row covers precision 1000000 sizing without saturation).
