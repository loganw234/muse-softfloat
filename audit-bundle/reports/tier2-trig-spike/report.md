## 5. Original algorithm design (brief item 4)

All of the below is designed here from the mathematics and
this codebase's existing shapes; no third-party source,
constants, or polynomials informed it. Taylor coefficients
are factorial reciprocals (mathematical constants, derived
exactly); pi and the scaled coefficients are generated by
*our* MPFR/mpmath side at build time and committed as
integer limb tables with regeneration refusal, per SF-1
Section 6.2 - never copied tables, never decimal literals.

### 5.1 Exact reduction (all magnitudes, integer-only)

Decode with the existing `msf_decode` (value = sig * 2^exp,
sig < 2^53, fits `uint64_t` via `msf_u128_to_u64_trunc`).
Let a = |x| (cosPi even, sinPi odd - input sign applied
once at the end for sinPi, never for cosPi). Split exactly
a = I + f, I integer, f in [0,1): pure shifts/masks on
(sig, exp); if exp >= 0 then f = 0 exactly, however huge a
is - this is the whole Fork B advantage, period reduction
is *exact* at any magnitude in every format. Nearest-
integer form: if f <= 1/2: n = I, r = f; else n = I+1,
r = f-1 (negative). Only the parity of n and the exact
dyadic r (|r| <= 1/2, at most 54 significant bits) survive.
sinPi(x) = sgn(x)*(-1)^n*sinPi(r), cosPi(x) =
(-1)^n*cosPi(r). Quadrant fold with t = |r| in [0, 1/2]:
t <= 1/4 uses kernels Ks(t)=sin(pi*t), Kc(t)=cos(pi*t)
directly; t in (1/4, 1/2] uses t' = 1/2 - t (exact) with
sin<->cos swapped. Kernel range: t in [0, 1/4], i.e.
u = pi*t in [0, pi/4 ~ 0.7854]. Exact branches inside the
reduction, before any polynomial: r = 0 (x integral:
sinPi = signed zero, cosPi = (-1)^n exactly) and t = 1/2
exactly (sinPi = +/-1 exact by the sign formula, cosPi =
zero; reached as t' = 0). No other input gives a rational -
hence exactly representable or midpoint - result: for
rational multiples of pi a rational sine/cosine lies in
{0, +/-1/2, +/-1} (Niven's theorem), and +/-1/2 would need
|r| = 1/6-class values that are not dyadic, so no dyadic
input outside the branches is exact or a tie. The parcel
carries this argument (with its citation/proof) because
two things ride on it: inexact is *always* signalled
outside the branches, and the Ziv loop below can never be
asked to decide a true zero distance.

### 5.2 Kernel shape: one shared wide float, two stages

Values inside the kernel are (W-bit unsigned significand,
int32 exponent, sign where needed) "wide floats" over
32-bit limbs - the `msf_wide.c` limb style extended with
the missing wide*wide multiply, jam-shifts, and
add-with-alignment the Clause 9 survey already priced as
new infrastructure. One helper, one kernel TU
(`src/msf_math.c`-shaped, all three formats together per
SF-1 Section 8), formats differing only in the final
existing pack (`msf_pack_f16/f32/f64` over
`msf_pack_generic`, unchanged). No hardware FP types, no
alloc, no state.

u = pi_W * t (t exact dyadic -> one wide multiply by the
generated pi limbs), z = u*u, then
Ks = u * S(z), Kc = C(z) with S/C the Taylor series in z.
Our sizing arithmetic (`kernel_sizing.py`, log
`out/kernel_sizing.log`; rigorous form for the parcel:
integer remainder bounds by first-neglected-term times
1/(1-ratio), sin(u)/u >= 0.9003 on the range so absolute
and relative targets differ by < 0.16 bit):

| target truncation | sin terms | cos terms |
|---|---|---|
| 2^-140 | 17 | 18 |
| 2^-160 | 19 | 19 |
| 2^-200 | 22 | 23 |

Two stages from **one** coefficient table generated at
W2 = 224 bits for the 2^-200 row (45 coefficients x 28 B
+ pi ~ **1.3 KB** total, all formats):
- Stage 1: W1 = 160 bits, first 17/18 terms (top limbs of
  the same coefficients; coefficient re-derivation for
  stage 1 is part of the generator, truncation bound
  re-proved at that row). Total proven error bound budget
  (truncation + coefficient rounding + Horner rounding,
  each accounted in wide ulps): E1 <= 2^-140 relative to
  the result binade. That already exceeds the measured
  f64 worst need (2^-111.6) by ~28 bits, so on `.wc`
  evidence stage 1 decides everything; the interval test
  in 5.3, not this comparison, is what makes any single
  result correct.
- Stage 2: W2 = 224 bits, all 22/23 terms, E2 <= 2^-195
  relative. Decides any input whose genuine extra is
  below ~140 - i.e. the f64 leg survives even if the true
  hardest case were 80 bits harder than anything in the
  published sets.

Error accounting shape (the parcel's WIDTHS-style note):
each wide op jams to W bits with a stated per-op error
<= 1 ulp_W plus a sticky-aware direction, coefficients
carry generator-proved rounding <= 1/2 ulp_W2 (stage 1
uses their top bits, error <= 1 ulp_W1, re-stated), pi_W
same, Horner accumulation bounded by term_count *
per-op bound amplified by partial-sum magnitudes <= 1;
truncation by the Taylor row. The result is a closed-
form integer E per stage, computed at generation time and
checked by the constants generator - no hand-waved
constants ship.

Tiny-argument regimes need no third polynomial: because
kernel values are wide *floats*, u ~ 2^-1072 is just a
normal significand with a very negative exponent; Ks = u*S
with S ~ 1 and Kc evaluated in the delta form below. The
only scale trap is the flat extremum, next.

### 5.3 Directed modes: interval pack (argued choice)

Chosen: **nearest-plus-neighbour interval decision over
the existing pack**, not roundToOdd. Reason: the pack
interface already rounds one wide (sig, sticky, exp2)
correctly in every mode and is gated; roundToOdd would
add a fifth internal pack mode *and* still needs an
escalation story (computing roundToOdd at p+2 faces its
own finer-grid margin), while the interval argument needs
only monotonicity of a rounding we already own:

1. Stage k produces A with a *proven* |A - y| <= Ek in
   absolute terms at y's scale (converted from the
   relative bound via A's exponent; for subnormal-scale
   results Ek is formed against the subnormal quantum
   directly).
2. Form lo = A - Ek, hi = A + Ek exactly as (sig, sticky,
   exp2) pack inputs (wide subtract with jam; lo/hi are
   not approximations of the endpoints - they are
   endpoints rounded outward to the pack's input grid).
3. Pack lo and hi under the caller's rounding attribute.
   If bits **and flags** agree, that is the correctly
   rounded result for y: rounding (value and the
   after-rounding tininess judgement the pack makes) is
   monotone in the exact operand, and y in [lo, hi].
   Inexactness: outside the Section 5.1 exact branches y
   is irrational (Niven), so inexact is semantically
   always set there; the acceptance test requires flag
   agreement of the endpoints' packs and the kernel
   asserts inexact in non-branch results, with underflow
   taken from the agreed pack judgement - if the endpoint
   packs disagree on tininess at the 2^emin edge, that is
   simply an undecided interval and escalates.
4. If bits or flags differ, go to stage 2. If stage 2 is
   still undecided, the input is harder than the leg-(c)
   margin claims exist; the kernel must not guess
   silently in that world, so the design's termination is
   a proof obligation, stated next - there is no third
   stage on the target, deliberately, because the RP2040
   cost model wants a fixed stack footprint.

The flat-extremum (saturation) family is decided inside
the same framework, not by extra width: whenever the
folded kernel is cos-shaped (Kc(t), or Ks via t' near
1/2), the kernel computes delta = 1 - cos(u) =
(z/2) * D(z) with D a short series (its own generated
table row, derived from the cosine series algebraically
by us at generation time), as a wide float with its own
exponent - delta ~ 2^-2146 for the smallest f64 input is
an ordinary wide float. The pack inputs for y = 1 - delta
are then formed exactly at the pack's scale: for delta
below the destination's sub-unity quantum the jammed
significand is "1 minus sticky", and the interval test
uses delta's *relative* interval [d_lo, d_hi] mapped
through the subtraction, so directed correctness near +/-
1 follows from delta > 0 and its comparison against
representable thresholds, both wide-integer facts. This
is also the branch that makes the fenced foreign binary's
measured failure mode (directed cosPi near 1, Step 0b)
structurally impossible here.

### 5.4 Specials and NaN delivery

Semantics from SF-1/S1 pins (Clause 9.2.1 via S1 extracts
and the Clause 9 survey's common-semantics summary,
`scratch/tier2-clause9/report.md` 4.6.1); the parcel
re-reads the 9.2.1 table with a second reader at its
entry gate, as SF-1 requires - the two zero-sign cells
below are the ones that reading must confirm:

| input | sinPi | cosPi | flags |
|---|---|---|---|
| sNaN | qNaN (operand quieted) | same | invalid |
| qNaN | qNaN (operand) | same | - |
| +/-inf | default qNaN | same | invalid |
| +/-0 | +/-0 (sign of x) | 1 | - (exact) |
| integer n (finite) | +/-0 (sign of x) | (-1)^n = +/-1 | - (exact) |
| half-integer n+1/2 | +/-1 (by reduction signs) | +0* | - (exact) |
| other finite | rounded kernel value | same | inexact always; underflow iff tiny+inexact after rounding (pack judges); never overflow/divideByZero |

\* cosPi zero sign at half-integers believed +0 in all
modes (cosPi even); second-read item. sinPi zero sign at
negative integers believed sign-of-x (odd function),
second-read item; this spike's f16 files encode it that
way (Section 3) and flag the assumption here rather than
burying it.

NaN delivery is the existing matrix unchanged:
`msf_nan_delivery(dfmt=fmt, ops=[decoded], n=1,
invalid_without_nan = is_infinity)` - sNaN hits clause
(b) (invalid + first signaling operand quieted), qNaN
hits (c), infinity hits (a) (invalid + default qNaN).
sinPi/cosPi are not among the 9.2.1 NaN-exception families
(hypot/pow class in the survey), so wholesale matrix
reuse is legitimate; homogeneous formats mean payloads
never convert. Flags come from the pack + matrix only -
MPFR flags are never transcribed (Step 0b).

### 5.5 Leg-(c) proof obligation, stated as the parcel carries it

Per format, exactly one of these closes the bundle:

- **binary16:** exhaustion replaces the margin argument.
  The gate is the proof for the shipped logic (63,488
  finite inputs x 2 x 4 modes against MPFR-decided
  values; SF-1/clause9 call f16 exhaustion complete
  evidence). Kernel-side, the same stage-1 error bound
  (E1 <= 2^-140 relative) trivially exceeds the
  exhaustively measured f16 need (significand p + 17.75
  bits at the worst input), so
  the interval test also always decides at stage 1 -
  two independent stories, either suffices.
- **binary64:** fixed-stage termination from the
  published worst-case gap. Obligation shape: (i) quote
  the authority (Section 2: full-range binary64 `.wc`
  sets; worst cases known for sinpi/cospi in double
  precision); (ii) recompute the margin over the sets
  with our decider (this spike: 58.58 bits max extra,
  i.e. every true value is at least 2^-111.6 binade-
  relative from every rounding boundary, saturation
  family separated and handled by the delta proof);
  (iii) prove stage-2 Ek bound <= 2^-195 relative from
  the coefficient/truncation/Horner accounting; (iv)
  conclude the stage-2 interval always decides, with
  ~83 bits of slack absorbing accounting pessimism.
  What is *believed* rather than *measured* is (i) -
  completeness of the published sets. That is the
  standard SF-1 ladder shape (leg (a) feeds leg (c)),
  and the spike's residual risk statement prices it in
  Section 6.5.
- **binary32:** leg (c) by exhaustive MPFR-decided
  differential over all 2^32 inputs x 2 functions x 4
  modes (Section 4 arithmetic: ~7.96 h single-core at
  measured MPFR rate, shardable), i.e. complete evidence
  for the host-built kernel logic replacing a gap
  argument that cannot be quoted (none exists in allowed
  sources) and cannot be searched BaCSeL-style inside
  this window. The interval kernel design is shared, so
  the same stage bounds apply, but f32's *termination*
  proof, if the lead wants one beyond exhaustion, would
  need the exhaustive run to also dump its hardest
  margins - cheap to add while the wide values exist,
  priced as an option, not assumed. Board-build
  equivalence is sampled replay, as elsewhere in the
  project; exhaustion verifies logic, board vectors
  verify the target build on directed samples.

### 6.1 Code size

Anchors (measured this spike by line count): existing

| piece | estimate (est.) |
|---|---|
| Wide-float helper (W<=224 mul/add/jam/normalize, WIDTHS row) | 220-300 lines |
| Kernel TU: reduction+quadrant+both kernels, delta branch, interval-pack driver, specials, all formats | 450-600 lines |
| Per-format public glue (6 entries over generated dispatch) | 15-30 lines each, 90-180 total |

Kernel lines per format, as the brief asks: the design is

factor).

### 6.2 RP2040 footprint (design-derived)

Flash: kernel + helper text estimated **3-6 KB** Thumb
(est. from ~900 lines of limb C of `msf_wide.c` density;
the parcel measures exactly from the linker map per SF-1
Section 9 - no tighter number is honest before code
exists) + 1.3 KB rodata tables. Stack: fixed, no
recursion, no heap; live wide values bounded by
construction (u, z, accumulator, coefficient temp, A,
lo, hi at W2=28 B each + pack sig 16 B + spill) ->
**< 512 B worst-call stack** (est.), state zero bytes
(pure functions, per-core state contract untouched).
Existing harness shape already carries unary single-
result rows, so board replay needs **no new CDC shape**.

Latency (workload budget, from `kernel_sizing.py`
anchored on the silicon IAS15 record: 1.58 steps/s x
~13,100 f64 ops/step ~ 20,700 wrapped ops/s at 125 MHz,
`docs/RECORD.md` wave-3 close): stage-1 eval ~500 limb
products, stage-2 ~1,225, i.e. ~125-306 f64-mul
equivalents; at the (div/sqrt-loaded, hence pessimistic)
anchor that is roughly **1-15 ms per evaluation** across
stages and anchor interpretations. Twiddle configuration
for the SF-1 gate sizes (2 x N/2-ish evals, mostly stage
1): N=256 trivial, N=1024 ~ 1-8 s, N=4096 ~ 4-60 s
one-time. This is the widest error bar in the report; the
parcel measures real cycles with the IAS15-style RATE
apparatus. If N=4096 configuration time offends the
demo, the mitigation is workload-side (configure once,
smaller gated headline size) - not a kernel change.

### 6.3 Intra-parcel sequence f16 -> f32 -> f64

1. **Day 0-1: helper + f16.** Wide helper with its own
   exact unit gates; kernel stage 1; f16 rows; exhaustive
   host gate (seconds to generate, runner minutes) =
   the kernel-correctness proof point. Measure kernel
   host throughput now (Section 4's open rate). Bundle
   checkpoint 1: f16 exhaustive green or stop and
   rethink while it's cheap.
2. **Day 1-2: f32.** f32 glue; foreign RN exhaustive
   pre-screen (~2 min) to shake out gross defects,
   MPFR-adjudicate every disagreement; directed
   screening with sinpif in all modes and cospif
   *outside* a generously fenced saturation region
   (|reduced t| >= 2^-4), MPFR deciding inside it; then
   launch the exhaustive MPFR-decided differential
   sharded by sign/exponent bands in the background
   (~7.96 h single-core equivalent, overnight-parallel),
   with hardest-margin dump enabled (buys the f32
   termination number as a by-product).
3. **Day 2-3: f64 (while the f32 shards run).** Same TU,
   f64 glue; full `.wc` gate (118,592 inputs x 4 modes,
   MPFR-decided expected values regenerated by the
   parcel's own MPFR generator in the shape of this
   spike's redecide+aggregate, provenance-tagged as
   foreign-input/MPFR-decided); stage-2 escalation
   exercised and counted (expected escalations on `.wc`:
   near zero if stage-1 bound is honest - the count
   itself is a leg-(c) health readout); directed +
   seeded MPFR volume (~200k inputs, minutes at Section
   4 rates); leg-(c) note written (Section 5.5).
   Checkpoints 2-3 (either order): `.wc` 100% PASS in
   all modes, and f32 exhaustive log complete with zero
   unexplained disagreements.
4. **Day 3-5: closure.** Board sampled replay per row
   (1-2k directed cases/row through existing harness,
   hash-compared), linker-map flash accounting, negative
   controls permanent, verifier (planted-copy) pass,
